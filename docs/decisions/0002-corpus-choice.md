# ADR-0002: CNN/DailyMail as the corpus

## Status
Accepted

## Date
2026-09-22

## Context
The assignment requires "a sizable corpus" and, separately, an evaluation
step that measures "the quality of summaries using automated metrics (e.g.,
ROUGE scores)". ROUGE requires a human-written reference summary per
document. Under an EOD deadline, hand-labeling reference summaries for a
custom corpus was not feasible.

## Decision
Use the CNN/DailyMail dataset (`abisee/cnn_dailymail`, config `3.0.0`, the
non-anonymized variant), pulled via HuggingFace `datasets`. Each row ships
`article` (body text) and `highlights` (human-written reference summary),
so ROUGE evaluation is possible without extra labeling work. We draw 500
articles from the `test` split for the corpus, and a random 15-article
*subset of that same corpus* (not held out) for retrieval/summary eval,
seeded (`random.seed(42)`) for reproducibility.

## Alternatives Considered

### Wikipedia articles
- Pros: broader topic diversity, tests general-knowledge search better.
- Cons: no built-in reference summaries — would need either human
  labeling (not feasible tonight) or LLM-generated "gold" summaries,
  which would make the ROUGE score circular (LLM graded against
  another LLM's opinion of a good summary).
- Rejected: CNN/DailyMail's human-authored highlights avoid that
  circularity.

### BBC News subset
- Pros: similar shape to CNN/DailyMail (news + summary).
- Cons: less standardized tooling/availability via `datasets` compared
  to CNN/DailyMail, which is a long-established summarization benchmark.
- Rejected: CNN/DailyMail is the more common baseline, making our ROUGE
  numbers easier to sanity-check against published literature.

### User-supplied corpus
- Cons: no reference summaries, requires the user to source and clean
  documents themselves within the same night.
- Rejected for this run, but the pipeline (`rag/data_prep.py`) is not
  hardcoded to CNN/DailyMail specifically for search/summarization —
  only the *evaluation* step depends on `highlights` existing.

## Consequences
- ROUGE scores in the report are only meaningful in the context of our
  summarization style (fluent paragraph) vs. CNN/DailyMail's reference
  style (three-sentence, telegraphic bullet highlights) — this stylistic
  mismatch depresses ROUGE even when the generated summary is factually
  accurate (documented with an example in `REPORT.md`).
- Test-set queries are generated by an LLM reading the article itself
  (see `docs/decisions/0004-evaluation-methodology.md`), not by users,
  so retrieval accuracy numbers measure "can the system find the article
  its own content implies" rather than real user query diversity.
- Corpus size (500 docs) is small by production standards; scalability
  beyond this is discussed as a known limitation in `REPORT.md` (BM25 and
  `IndexFlatIP` are both O(n) per query — see ADR-0001 Consequences).
